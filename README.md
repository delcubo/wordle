# Wordle Group Game — платформа для розыгрышей

Закрытый сайт (аналог wordle.belousov.one) для проведения нескольких параллельных
розыгрышей в Wordle с разными правилами, доступ — по персональным ссылкам,
администрирование — через отдельную панель.

## Модель данных

- **User** — глобальная личность человека, одна постоянная персональная ссылка
  (`/play/<токен>`) на все розыгрыши, куда его подключит администратор
- **Tournament** — один розыгрыш одного из трёх типов:
  - `standard` — простое распределение мест по очкам за N дней
  - `championship` — тот же стандартный этап + тай-брейк при равенстве очков +
    плей-офф (сетка на выбывание) среди топ-2ⁿ мест
  - `knockout` — розыгрыш на вылет с самого начала для 2ⁿ участников; пары
    первого раунда администратор расставляет вручную (рейтинга для автопосева ещё нет)
- **TournamentEntry** — участие конкретного User в конкретном Tournament со своим
  позывным (в разных розыгрышах у одного человека могут быть разные позывные)
- **DailyWord** — слово дня конкретного розыгрыша, со статусом `suggested` /
  `confirmed` (см. ниже)

Несколько розыгрышей могут идти параллельно и независимо: если человек подключён
к двум активным розыгрышам, каждый день он решает два разных слова — по одному
на розыгрыш.

## Подтверждение слова дня

Система заранее предлагает слово на ближайший ещё не наступивший день (алгоритм
детерминированный — см. `api/dictionary.py`). Администратор в своей панели может:
- согласиться с предложенным словом,
- заменить его вручную (с проверкой по словарю и на отсутствие повтора в рамках розыгрыша).

**Дедлайн — начало дня** (00:01 по таймзоне из `TOURNAMENT_TIMEZONE`). Как только
день наступил, менять слово уже нельзя — если администратор ничего не подтвердил,
действующим становится предложенное системой слово автоматически, без каких-либо
дополнительных действий с его стороны.

## Защита от мошенничества

Прогресс (число использованных попыток, угадано/не угадано) хранится в БД,
привязан к `TournamentEntry`, а не к устройству или браузеру — открытие личной
ссылки с другого устройства покажет тот же прогресс, а не чистый лист
(см. `api/routers/game.py`, `api/crud.py::get_or_create_attempt`).

## Структура репозитория

```
wordle-app/
├── api/
│   ├── main.py                # FastAPI: роутеры + отдача собранного фронтенда (SPA)
│   ├── database.py             # подключение к БД (async SQLAlchemy)
│   ├── models.py                 # User, Tournament(+type), TournamentEntry, DailyWord(+status), Attempt, плей-офф
│   ├── schemas.py                 # Pydantic-схемы запросов/ответов
│   ├── crud.py                     # весь доступ к БД в одном месте
│   ├── scoring.py                    # чистая логика очков/мест/флагов (без БД)
│   ├── standings_view.py              # собирает данные из БД в форму для scoring.py
│   ├── wordle_logic.py                 # раскраска попытки (🟩🟨⬜)
│   ├── dictionary.py                    # словарь, детерминированный подбор + валидация ручной замены
│   ├── admin_auth.py                     # cookie-сессия администратора (пароль из .env)
│   ├── tournament_time.py                 # расчёт "какой сегодня день розыгрыша"
│   ├── data/russian_words.txt              # 26 470 русских слов из 5 букв
│   └── routers/
│       ├── game.py                          # my-tournaments / today / guess (по токену + tournament_id)
│       └── admin.py                          # users / tournaments / entries / words / standings
│
├── webapp/                    # React + Vite, собирается в статику
│   └── src/
│       ├── main.jsx             # роутинг: /play/:token, /play/:token/:tournamentId, /login, /admin
│       ├── components/
│       │   ├── WordGrid.jsx       # сетка 5×6
│       │   └── Keyboard.jsx        # клавиатура с подсветкой
│       └── pages/
│           ├── MyTournaments.jsx    # список розыгрышей игрока
│           ├── PlayerGame.jsx        # игра в конкретном розыгрыше

├── requirements.txt
├── nixpacks.toml                # billd-конфиг Railway (Python + Node в одной сборке)

```

## Локальный запуск

1. `cp .env.example .env`, задать `ADMIN_PASSWORD`, `SECRET_KEY`, `DATABASE_URL`
2. `pip install -r requirements.txt`
3. `alembic upgrade head`
4. Backend: `uvicorn api.main:app --reload --port 8000`
5. Фронтенд (для разработки с hot-reload): `cd webapp && npm install && npm run dev`
6. Для продакшен-сборки: `cd webapp && npm run build` — тогда backend сам отдаёт
   собранный фронтенд на всех путях

## Деплой на Railway

1. Создать проект на [railway.app](https://railway.app), подключить репозиторий из GitHub
2. Добавить PostgreSQL-аддон в тот же проект — Railway сам пропишет `DATABASE_URL`
3. Задать `ADMIN_PASSWORD`, `SECRET_KEY`, `TOURNAMENT_TIMEZONE`
4. Сборка настроена в `nixpacks.toml` — ничего вручную настраивать не нужно
5. Домен — Railway → Settings → Networking → Custom Domain, прописать CNAME у
   регистратора; HTTPS-сертификат Railway выпускает и обновляет сам

## Статус реализации

Готово и протестировано (сквозные тесты с несколькими розыгрышами, одним
пользователем в двух розыгрышах сразу, подтверждением/заменой слова, дедлайном
по дате):
- Полная схема БД под все три типа розыгрышей, тай-брейк и плей-офф (модели есть;
  автоматическая бизнес-логика тай-брейка/плей-офф — предмет следующего этапа)
- Глобальные пользователи с одной постоянной ссылкой на все розыгрыши
- Подключение пользователя к розыгрышу с индивидуальным позывным
- Подтверждение/замена слова дня администратором, дедлайн = начало дня
- Подсчёт очков, таблица с флагами пропуска, места с учётом равенства
- Экран "мои розыгрыши" на стороне игрока + игра в конкретном розыгрыше
- Админ-панель: игроки, розыгрыши (с выбором типа), участники, слово дня, таблица

Не реализовано (следующие этапы):
- Бизнес-логика тай-брейка и плей-офф/сетки на вылет (создание пар, автопродвижение
  победителей, sudden death, генерация изображения сетки) — модели в БД готовы
- Более "чистый" список слов именно для ответов (сейчас включает словоформы)
- UI-полировка (сейчас инлайн-стили, минимально достаточный вид)
